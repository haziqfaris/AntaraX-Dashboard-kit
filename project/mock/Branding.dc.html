REKA SOP · CLIENT BRANDING

The client's brand on top, our standards underneath

If the client has a brand kit, the project adopts it. If not, it uses REKA's default: the neutral base with the client's logo and one colour. Either way, the bare minimum every application must have stays the same (owner, 16 Oct 2026).

At kick-off

1 Ask: does the client have a brand kit? Brand guidelines, logo files, colours, fonts. Ask in the kick-off checklist, before any screen is drawn.
2 · YES Collect Logo as SVG: full colour, white, one colour · colours and what each is for · typefaces and the web licence · photography or illustration · tone of voice · letterhead
3 · YES Map onto the base Their colours become the base's variables; their typeface replaces IBM Plex. Written down once in client-brand.json
4 · BOTH Standards check Contrast, focus, status meanings, places, credit and the colour script (below). Where the brand fails one, the standard wins and we say how.
5 · BOTH Client signs off The sign-in page and one working screen, in their look, before the build goes wide. Recorded in the project's decisions.
2 · NO REKA's default The neutral base · the client's logo, or their name set as a wordmark in IBM Plex Sans · one primary from the default set, chosen with the client. Also written in client-brand.json

The client's brand decides

  • The logo, and the wordmark beside it
  • The primary colour, and a secondary for charts and highlights
  • The typeface, where it is licensed for the web
  • Photography, illustration and the sign-in panel
  • The tone of the words on their own pages
  • Letterhead on documents, and how emails look
  • Corner rounding, within 4 to 12px

Our standards decide, whatever the brand

  • Where things are: the top bar's order, Help, the account at the far right, the standard pages
  • The shared words and roles
  • Contrast: text 4.5:1. A brand colour that fails is darkened until it passes
  • A visible focus ring; 44px touch targets
  • Status colours by meaning, always with the word
  • Every wait animated; forms, passwords, data and security ("Built right")
  • "Built by REKA" in the footer; YaraOne for help and feedback
  • No AntaraX font, colour, mark or word

The default set, when there is no brand kit

Six primaries, each passing 4.5:1 with white text and none of them an AntaraX colour. The client picks one; the base does the rest.

client-brand.json: the brand, written down once

{
  "client": "Harbour Logistics Sdn Bhd",
  "source": "Harbour brand guidelines v3 (2025), received 16 Oct 2026",
  "logo": { "full": "brand/logo.svg", "white": "brand/logo-white.svg", "mark": "brand/mark.svg" },
  "colours": { "primary": "#0F4C5C", "secondary": "#E9A23B" },
  "fixes": { "secondary-text": "#8A5A12: their amber fails 4.5:1 as text, so text uses this darker shade" },
  "type": { "sans": "Manrope", "licence": "SIL Open Font License" },
  "radius": "10px",
  "signedOff": { "by": "[CLIENT CONTACT]", "on": "[DATE]" }
}
The theme is generated from it, and the colour script allows its colours even where one happens to match an AntaraX colour, because they are the client's own.
